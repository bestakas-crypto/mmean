■ 핵심 설계 원칙 (변경 금지 사항 — 반드시 숙지)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. LLM은 사이즈(크기)만 조정 — 방향/진입/청산 결정 절대 불가
   - weight_adjust ±20% (clamp) → order_size에만 영향
   - position_engine.py 상단 주석 참고

2. FlowEngine 파이프라인 연속값 원칙
   - flow_score: -2.0~+2.0 연속 float (sign() 이산화 금지)
   - regime_weight: sigmoid 연속 함수 (최솟값 0.05 하한 보장, 0.0 금지)
   - 레짐 라벨(STRONG_LONG 등)은 모니터링/로깅 전용, 주문 계산 사용 금지

3. Easy / Expert 모드 분리 (혼용 금지)
   - Easy: levels_v2.json (C:/mme/workspace/levels_v2.json) 레벨 1~20 프리셋
   - Expert: ConfigManager 개별 파라미터 직접 조정
   - Easy 모드 활성 시 /api/config POST → 409 에러 반환

4. 야간 모드 현재 비활성화
   - session_detect.py: night 입력 시 "day"로 대체 적용 (경고 출력)
   - NightRegimeEngine 코드는 존재하나 실제 사용 안 함
   - night_auto_run.py, scripts/night.py 도 현재 비운영

5. LLMGate 조건
   - |flow_score| >= 0.8 → 강한 추세 → LLM 스킵
   - |flow_score| < 0.8 → 전환 구간 → LLM 호출
   - 추후 확장 예정: basis_pct, oi_delta_pct, volatility_state (GateInputs에 stub 존재)

6. LLMCaller 안전장치 (6가지 실패 모두 처리 필수)
   - timeout / JSON parse fail / schema mismatch / rate limit / provider fail / confidence<0.55
   - 실패 시 weight_adjust=0 → 엔진 기본 규칙만으로 진행 (거래 중단 아님)

7. 서킷브레이커 / 하드스톱
   - 동일 에러 3회 연속 → 서킷 오픈 (60s 후 half-open 재시도)
   - 동일 에러 5회 연속 → 하드스톱 (수동 resume 필요: /api/engine/resume)

  KIS WebSocket tick
    → engine_runtime.engine_loop() (0.5s)
        → BiasRegimeEngine → bias, entry_signal, confidence
        → ForeignFlowEngine → flow_score
        → FlowRegimeEngine → long_weight, short_weight
        → LLMGate → should_call?
           ├─ Yes → LLMInputBuilder → LLMCaller → weight_adjust
           └─ No  → weight_adjust = 0 (이전 TTL값 유지)
        → LLMEmaFilter → weight_adjust_filtered
        → LLMTTLManager → TTL 감쇠
        → PositionEngine → order_size = base × regime_weight × (1 + weight_adjust_filtered)
        → SimEngine → 가상 체결 (실거래 엔진과 별도)
        → RegimeRecorder → mmean.db regime_ticks INSERT

[4] rag/rag_prep.py — 3단계 배치 전처리 (장 마감 후 실행)
──────────────────────────────────────────────────────────────────────────────

  실행: python rag/rag_prep.py [--step 1|2|3] [--days N] [--db PATH]
  스케줄: 장 마감 후 1회 (16:30 또는 야간 종료 후 06:30 권장)

  Step 1: regime_ticks → market_features (구간화)
    처리: LEFT JOIN으로 미처리 tick만 선별
    feature_vector JSON: {time_bucket, basis_zone, volume_zone, daily_pnl_zone, long_score, short_score, bias}
    time_bucket: morning(9~11) / midday(11~14) / late(14~16) / night_early / night_late
    basis_zone: strong_pos/mid_pos/neutral/mid_neg/strong_neg
    volume_zone: burst(≥1.6) / normal / quiet(≤0.6)
    regime_tags: pattern_schema.classify_regime_tags() 호출 → JSON 저장
    1000건 단위 배치 INSERT

  Step 2: trades + market_features → pattern_memory (클러스터 집계)
    cluster_key = "basis_zone|volume_zone|time_bucket"
    집계: total, wins, losses, pnl_sum, mae_sum, mfe_sum, long/short별 승패
    UPSERT (ON CONFLICT cluster_key DO UPDATE)
    warning_level 자동 계산:
      danger  : win_rate<0.25 AND avg_pnl<-0.5
      warning : win_rate<0.35 AND avg_pnl<-0.2
      caution : win_rate<0.45
      none    : 정상 (또는 샘플<5)

  Step 3: llm_calls → llm_evaluations (LLM 점수 사후 평가)
    opportunity 레이어 호출 + 미평가 건만 처리
    유효 시간(expires_at) 내 진입 거래와 매핑 (없으면 5분 기준)
    score_vs_pnl 라벨: high_score_win / high_score_loss / low_score_win / low_score_loss
    진입 없으면 → 'no_entry' 기록

  핵심 함수 (실시간 활용):
    get_pattern_warning(db_path, basis_zone, volume_zone, time_bucket)
      → warning_level != 'none'이면 경고 문자열 반환
      → llm_filter._build_prompt()에서 프롬프트 주입용
    get_llm_score_stats(db_path, days)
      → LLM 점수 구간별 승률 통계 (Analytics 대시보드용)
