결정 1: "레짐 ≠ 진입"으로 분리
  현재 MMEAN: [레짐 확정] = [진입 결정] → 5~12분 후행 구조적 한계
  Entry RAG 역할: 레짐이 LONG/SHORT를 결정한 뒤,
                  "지금 이 45초가 진입 적합 타이밍인가?"를 마이크로 신호로 판단

결정 2: 2단계 구현 (Phase 1 → 2)
  Phase 1 — XGBoost 단독 (데이터 800건 후)
    이유: 벡터 RAG는 데이터 부족 시 오히려 노이즈. 모델 하나가 가볍고 빠름.
  Phase 2 — ChromaDB RAG 추가 (2,000건 후)
    이유: 충분한 사례가 쌓이면 "왜 이 패턴이 실패했나" 설명 가능.

결정 3: 스냅샷 윈도우 45초
  60초: LLM 응답 지연(3~5초)과 겹쳐 오염 가능성
  30초: 너무 짧아 노이즈 우세
  45초: Grok 추천 채택 (근거 가장 명확)

결정 4: 레이블 = ATR 기반 상대값
  절대값(pnl_ticks) 레이블은 변동성 큰 날과 횡보장을 같은 기준으로 판정 → 부당
  pnl_atr_ratio = pnl_ticks / session_ATR (오늘 ATR 중앙값)
  session_phase별 SUCCESS 기준 차등 (MORNING ±2ATR / MIDDAY ±1.5ATR / LATE ±1ATR)

결정 5: entry_snapshots는 mmean.db에 저장
  intraday.db는 휘발성 → 학습 데이터 손실
  mmean.db의 entry_snapshots에 영구 보존 (Claude 고유 판단)

결정 6: 기존 entry_gate 구조에 통합
  신규 4번째 상태 불필요. 기존 REJECT/HALF/ALLOW 구조 안에 Entry RAG 결과 주입.
  whipsaw_risk > 0.70 → REJECT (강제), > 0.45 → HALF (ALLOW인 경우만)
  초기에는 경고 플래그만 발행 (패턴 분석 우선), 실제 REJECT는 A/B 검증 후

결정 7: 새 스레드 금지 — 메인 틱 루프 인라인 호출
  TRACK_CHECK_SEC=30 freeze 버그 미수정 상태에서 스레드 추가는 위험
  Entry RAG scorer는 모델 파일 로드 후 predict() 직접 호출 (< 1ms)

  [mmean.db 신규] entry_snapshots — 학습 데이터 영구 보존
  ─────────────────────────────────────────────────────────
  CREATE TABLE IF NOT EXISTS entry_snapshots (
      id                    INTEGER PRIMARY KEY AUTOINCREMENT,
      entry_ts              TEXT NOT NULL,
      session_date          TEXT NOT NULL,
      session_phase         TEXT,
      bias                  TEXT,
      features_json         TEXT,          -- 피처 벡터 JSON (45초 집계)
      pnl_ticks             REAL,          -- 사후 레이블 (NULL → 미완료)
      pnl_atr_ratio         REAL,          -- pnl_ticks / session_ATR
      max_adverse_excursion REAL,
      exit_reason           TEXT,
      outcome_class         TEXT,          -- SUCCESS / NEUTRAL / FAILURE
      atr_at_entry          REAL,          -- 레이블링 기준 ATR 값
      model_version         TEXT DEFAULT 'none',
      created_at            TEXT DEFAULT (datetime('now','localtime'))
  );
  CREATE INDEX IF NOT EXISTS idx_es_date ON entry_snapshots(session_date);
  CREATE INDEX IF NOT EXISTS idx_es_phase ON entry_snapshots(session_phase);

  [intraday.db 신규] entry_rag_infer_log — 당일 추론 이력 (휘발 가능)
  ─────────────────────────────────────────────────────────
  CREATE TABLE IF NOT EXISTS entry_rag_infer_log (
      id               INTEGER PRIMARY KEY AUTOINCREMENT,
      session_date     TEXT NOT NULL,
      ts               TEXT NOT NULL,
      enter_confidence REAL,
      whipsaw_risk     REAL,
      gate_result      TEXT,   -- ALLOW / HALF / REJECT
      features_json    TEXT,
      model_version    TEXT
  );
