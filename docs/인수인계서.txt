■ 프로젝트 개요
────────────────────────────────────────────────────────────────────────────────
KOSPI 200 선물 자동매매 시스템.
LLM 신호(레짐 판단) + Bayesian 파라미터 최적화 + RAG 기반 전략 선택 구조.

실행 환경 : Windows 10, Python 3.x (conda env: mmean)
주 저장소  : C:\mme\mmean\
DB 위치    : C:\mme\mmean\storage\
  mmean.db — 시장 데이터 (regime_ticks, session_patterns 등) [읽기전용]
  sim.db   — 시뮬레이션 결과 (sim_runs, sim_adoptions 등) [읽기쓰기]

■ 설계 원칙 (왜 이렇게 만들었나)
================================================================================

[Validation 원칙]
  훈련 날짜 ≠ 검증 날짜 (data leakage 방지)
  같은 레짐끼리만 검증 — 다른 장세에서의 실패는 파라미터 문제가 아님
  예: TREND_UP으로 훈련한 파라미터를 CHOPPY 날짜로 검증하면 의미없음

[레짐 기반 파라미터 라이브러리]
  sim_adoptions.train_pattern = 이 파라미터가 어떤 장세에서 검증됐는가
  실전에서: 오늘 레짐 판단 → 같은 레짐의 채택 파라미터 RAG 검색 → 적용

[데이터 충분성]
  현재 3일치 데이터 (2026-03-18~20) — 레짐별 1회씩뿐
  유의미한 RAG 선택을 위해서는 각 레짐당 3~5개 이상의 검증 통과 파라미터 필요
  목표: 6개월~1년치 (레짐이 여러 번 반복되어야 통계적 의미 생김)

[DB 분리 원칙]
  mmean.db — 시장 원본 데이터 (읽기전용, 절대 쓰지 않음)
  sim.db   — 시뮬레이션 결과 (쓰기, 정기 정리 가능)

■ 다음 작업 순서 (권장 워크플로우)
================================================================================

STEP 1. 패턴 등록
  → day_pattern.bat [1] 실행
    3일치 session_patterns 자동 생성

STEP 2. 올바른 검증 실행
  → sim.bat 실행 → [6r] 선택
    훈련날짜: 2026-03-18 (TREND_UP)
    범위: 가능한 TREND_UP 날짜가 포함된 범위 지정
    (현재 3일 중 TREND_UP = 3/18뿐 → 더 많은 데이터 필요)

STEP 3. 데이터 축적 자동화
  → day_auto_run.py 매일 실행 (sim.bat [A] 또는 스케줄러)
    random → bayes → validate([6r] 동일 로직) → adopt 자동 루프
    매일 1개 날짜씩 레짐별 파라미터 라이브러리에 쌓임

STEP 4. 채택 파라미터가 쌓이면
  → rag/sim_rag_builder.py 실행 → RAG 문서 빌드
  → 실전 매매 시 오늘 레짐 → RAG 검색 → LLM 파라미터 선택

STEP 5. sim_trades 정리 (주 1회 권장)
  → purge_sim_trades.bat [4] (3일 이전 trades 삭제)

■ 주의사항
================================================================================

1. day_pattern.py를 실행하지 않으면 [6r]에서 레짐 필터가 작동하지 않음
   → session_patterns에 데이터 없을 시 경고 후 전체 날짜 사용 (fallback)

2. sim_adoptions.train_pattern은 채택 시점에 session_patterns가 있어야 채워짐
   → 패턴 미등록 날짜의 파라미터는 train_pattern = NULL로 저장됨
   → 나중에 backfill 쿼리로 채울 수 있음:
      UPDATE sim_adoptions SET train_pattern = (
        SELECT p.pattern_type FROM session_patterns p
        WHERE p.date = substr(study_name, 5) AND p.session_mode = 'day'
      ) WHERE train_pattern IS NULL

3. validation 통과 기준 (_VALID_CRITERIA in day_sim.py):
   min_objective > 0, min_trade_count >= 5,
   max_drawdown >= -20틱, min_session_pos_ratio >= 0.50, min_robustness >= 0.40

4. 실전 매매 전 체크리스트 (모의거래 먼저):
   .env.public: KIS_ORDER_ENV=virtual, MMEAN_EXECUTION_ENABLED=true
   비밀번호 게이트 통과 후에만 WS 연결 + 포지션 동기화 실행됨
