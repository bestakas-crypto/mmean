[2026-03-24] [Flask / SQLite] 대시보드 1~2분마다 응답 정지 (Flask 스레드 고갈)
  증상: 대시보드 현재가 멈춤, /api/status 무한로딩, Firefox는 정상·Chrome만 먹통
        터미널에 "JudgmentLog open_event 실패: database is locked" 반복
  근본 원인:
    1. engine_runtime.py가 매 0.5초 틱마다 insert_tick() + flush_tick_batch() 호출
       → 매 0.5초 SQLite commit → WAL checkpoint 연속 발생
    2. busy_timeout=30000(30초) 설정으로 Flask 스레드가 DB lock 대기 시 30초 블로킹
    3. threaded=True Flask 서버가 요청마다 새 스레드 생성 → 30초 대기 스레드 누적 → 고갈
    4. llm_pulse.py가 5분마다 async thread 2개(duration update + insert) 생성 → lock 경쟁
    5. PulseEngine._history.append()가 DB insert 성공 시에만 실행
       → DB insert 실패(timeout) 시 대시보드에 "데이터 없음" 표시
    6. LLM max_tokens=200 → JSON 응답 잘림 → 파싱 실패 43.5%
  조치:
    - engine_runtime.py: flush_tick_batch() 매 틱 호출 제거 (5초 auto_flush로 대체)
    - regime_recorder.py: _FLUSH_INTERVAL=5.0, _auto_flush 스레드 추가
    - llm_pulse.py: async thread 2개 → 동기 호출로 변경 (5분 간격 부담 없음)
    - app_bootstrap.py: PulseScorer interval 60s → 300s
    - config_manager.py, param_store.py, judgment_log.py: busy_timeout 30000 → 2000
    - routes_core.py: /api/status에서 engine_lock 제거 (읽기 전용)
    - llm_chain.py: LLM_MAX_TOKENS 200 → 500
    - pulse_engine.py: _history.append()를 DB insert 조건 밖으로 이동 (항상 기록)
                       async thread → 동기 호출 변경
